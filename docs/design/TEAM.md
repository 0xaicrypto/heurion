# 研究团队协作

同一机构（租户）的成员可以共享一个研究项目，以及项目里的文档、数据集和分析。研究之外的个人文档、资料库和记忆仍然只属于本人。

## 1. 成员与角色

数据存在平台库的 `study_members(study_id, user_id, role, added_by, added_at)` 表里。

| 角色 | 谁 | 能做什么 |
| --- | --- | --- |
| owner（负责人） | 每个研究只有一个，与 `studies.owner` 同步 | 拥有 editor 的全部权限；还能加或移成员、改角色、转交负责人、删除研究、删除研究里的任何文档或数据集 |
| editor（可编辑） | 负责人加的本机构同事 | 读写研究里的文档（含实时协作、修订、AI 对话）、归入或移出文档与数据集、上传数据、筛选入组、生成研究数据集；可以删自己建的文档或数据集，不能删别人的 |
| viewer（只读） | 同上 | 读文档、数据集、分析，导出，评论（新建、回复、解决），和 AI 对话（AI 同样只读）；协同编辑器只读，服务端丢弃他发来的修改 |

- **同机构限制**：研究创建时记下 `studies.tenant_id`，即负责人当时所在的机构。成员必须与它相同，也就是同一租户、账号在用。个人机构里只有本人，所以个人机构的研究只能自己用。开发模式下没有机构的用户（`tenant_id` 为 null）同样不能加人。
- **转交**：只有负责人能转交，新负责人必须是本机构同事。原负责人留在研究里，角色改为 editor。
- **退出**：成员可以自己退出。负责人要先转交，才能退出。
- **离职交接**：机构管理员（`tenant_role=admin`）可以在 `GET /api/tenant/studies` 看到本机构全部研究，但只看得到标题、负责人和成员数，看不到内容。管理员可以用 `POST /api/studies/:sid/handover` 把负责人换成另一位同事，原负责人会被移出。管理员不因交接成为成员，也读不到研究内容。每次交接都写入审计，动作名为 `study.handover`。

## 2. 访问判定（`src/research/access.ts`）

所有「谁能看、谁能改」的问题都由这一个模块回答：`docRole`、`datasetRole`、`canAsset`、`canDelete`，以及等级判断 `allows(role, 'read' | 'write' | 'manage')`。

- **文档**：文档的 `docs.context` 若是 `{kind:'study'}`，权限按研究成员角色判断；否则只有主人（`docs.owner`）能访问。所以研究里的内容属于研究，创建者被移出研究后，连自己建的文档也看不到。回收站里的文档只有主人能恢复或彻底删除。
- **数据集**：`study_items` 里登记了归属研究的，按研究成员角色判断；否则只有主人能访问。
- **图片资产**：满足下面任一条件就能读：
  - 我是资产的主人；
  - 资产是用我能读的数据集画的分析图；
  - 资产被我参与的研究里的某份文档引用。按用户缓存 30 秒；成员变动或文档归入、移出时清空缓存。

### 用到访问判定的地方

- **接口**：
  - 文档路由前有一个中间件：GET，以及评论、对话、复制这几类 POST，只需要读权限；其余写操作需要 editor 及以上，权限不够时返回 403。非成员一律按资源不存在处理，返回 404。
  - 删除文档另外用 `canDelete` 判断。
  - 个人项目（文件夹）只能放主人自己、且不在研究里的文档。
- **MCP**：`Ctx.check`。写操作的工具需要 editor；`comment_reply` 和 `comment_resolve` 只需要读权限。`doc_list` 会带上我参与的研究里的文档，并标出所属研究、我的角色、创建者。`dataset_list` 和 `study_list` 也会带上共享项。
- **协同**：`collab/gateway.ts` 按角色放行连接。只读连接只处理客户端发来的 sync step1，客户端的 step2 和 update 一律丢弃。
- **服务层**：`DatasetService`（读、写、删）、`StudyService`（`own(user, id, level)`）、`ImageService`（插图要求 editor）。

## 3. 入组患者

- 入组仍要求操作者本人在患者的诊疗组里，这条规则不变。
- 筛选、入组、移出、生成研究数据集，需要研究里的 editor 及以上权限。
- 只读成员能看到入组人数、研究编号和研究数据集。患者代号只对能看到这位患者的人显示，也就是沿用患者库的可见性规则。
- 生成研究数据集时，只纳入操作者自己在诊疗组里的受试者，其余计入 skipped。
- 「患者数据不交给外部模型」这项机构设置照旧约束 AI，包括研究数据集。

## 4. AI 与记忆

- **AI 的权限**：AI 代表当前用户行事，用的是用户本人的 MCP 令牌，能力随用户在研究里的角色变化：只读成员的 AI 改不了文档，也管不了成员。
- **修改归属**：提交事件带上 `user`，即做出修改的人：
  - 接口写入用调用者；
  - 浏览器协同编辑按连接上标的用户计；一次合批里有多人编辑时，`user` 为 null。
- **记忆信号**：`memory/signals.ts` 只把信号记在 `user` 名下。共享文档里分不清是谁改的时候不记，别人的改法不会进我的记忆。不在研究里的文档只有主人能改，没有 `user` 时按主人记，保持原有行为。

## 5. 人机对等

| 界面 | MCP |
| --- | --- |
| 成员列表、可加的人、加人、改角色、移出、退出、转交 | `study_members`（action：list / candidates / add / set_role / remove / leave / transfer） |
| 研究列表（含共享） | `study_list`（role、shared_by、members） |
| 文档列表 | `doc_list`（研究里的文档：study、role、shared_by） |
| 离职交接 | 不给 AI，登记在 `NOT_FOR_AI`：这是机构管理员的人事操作 |

## 6. 测试

- **`tests/team.test.ts`**：
  - 权限矩阵：非成员、跨机构、editor、viewer、被移出；
  - 转交（原负责人失去管理权，被新负责人移出后看不到内容）；
  - 退出；
  - 离职交接（管理员只看到元数据、交接后也读不到内容、写入审计）；
  - 分析汇总包含所有成员画的图；
  - 个人文档不共享；
  - 记忆信号归属；
  - MCP 能力随角色变化。
- **`tests/isolation.test.ts`**：同机构同事先当 editor（正向对照：能读能改），再改成 viewer（能读不能写），最后被移出。移出后用他的账号调用每个带参数的接口，必须全部返回 4xx，响应里也不能出现暗号。新接口还要登记 `study_members.user_id`。
- **`scripts/ui-accounts.ts`**：两个账号走完整流程：加为 editor → 共享研究里标「共享」→ 协作者可见 → 实时编辑 → 改为 viewer → 编辑器只读、接口 403、研究页隐藏修改类按钮。

## 7. 以后

- 写作空间的个人文档还不能单独共享，目前只能经研究共享。
- 资料库还不能按机构或研究共享，比如科室共用的指南库。
- 研究成员的通知：被加入研究、被改角色时没有提醒。
